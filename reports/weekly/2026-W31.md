# 本周雷达 — 2026-W31

## 一句话总览
Agent 机会转向“可控落地”。

## 三个值得深挖的方向

## 1. **Agent 工作台：让人能看懂、接管、协作**

**数据支撑**

- [qm] HN：`qm – Multiplayer agent harness for work`，152 评论，强调多人/多 Agent 协作。
- [marbleos] HN：`What should the GUI for AI agents look like?`，77 评论，核心是 Agent GUI 和 human-in-loop。
- [autonomous-business-fail] HN：`We Gave GPT 5.6 Sol a Real Business. It Lied, Spammed, and Lost $447`，234 评论，说明“全自动经营”仍不可靠。
- [traceLLM] PH：`TraceLLM — OpenTelemetry for production AI applications`，生产级 AI 可观测性开始产品化。

**为什么这是机会**

现在的缝隙不是“再造一个 Agent”，而是：  
企业已经开始让 Agent 做真实任务，但缺少**状态可见、权限边界、审批、回滚、责任归属**。

现有方案两头都不够好：

- ChatGPT / Claude 适合个人交互，不适合团队流程沉淀。
- Zapier / RPA 偏确定性自动化，不适合长链路、不确定、需要人判断的 Agent 工作。
- Dev observability 工具看 trace，但业务用户看不懂“它为什么这么做”。

**机会点**：做一个面向 SaaS 运营/销售/客服团队的 Agent 控制台：任务队列、执行轨迹、人工审批、异常接管、团队协作，而不是底层 Agent 框架。

**与他的 SaaS 背景的契合点**

契合：

- SaaS 创始人通常懂多租户、权限、审计、团队协作、工作流状态机。
- 可以从现有 SaaS 场景切入，比如销售跟进、客服工单、客户成功续费提醒。

需要新能力：

- Agent trace 结构化。
- 人机协作 UX。
- 安全权限和执行边界设计。

**立即可做的小动作**

1. 访谈 5 个已经在用 Claude Code / ChatGPT / 内部 Agent 的 SaaS 团队，问：  
   “哪些任务你敢让 AI 做？哪些必须人工确认？出错后怎么追责？”
2. 做一个极简原型：  
   Gmail/HubSpot/Slack 中的 AI follow-up agent，但所有外发动作必须进入“待审批队列”。

## 2. **AI 成本与模型治理：从省钱工具变成系统记录**

**数据支撑**

- [deepseek-v4-flash] HN：DeepSeek V4 Flash 更新，343 评论；PH 也出现“frontier agent intelligence at Flash prices”。
- [gpt-5-6] HN：OpenAI `GPT‑5.6 price-performance frontier`，394 评论。
- [deepseek-analysis] HN：DeepSeek V4 Flash 性能/价格分析，311 评论。
- [llm-router-deprecated] HN：`Everyone is building LLM routers, we deprecated ours`，85 评论，说明“自动路由”本身可能在商品化。
- [depthdata] PH：`DepthData — system of record for your company's AI spend`。
- [langwatch-claude-cost] PH：`Claude Code usage tracking by LangWatch`。

**为什么这是机会**

模型价格正在快速下降，但企业成本问题没有消失，反而更复杂：

- 模型越来越多，团队各自接 API、买 Copilot、用 Claude Code。
- 成本不只在 token，还在失败重试、长上下文、Agent 循环、工具调用、工程师时间。
- 单纯 LLM router 价值变薄，因为模型厂商会直接优化价格/性能。

真正的缝隙是：  
**AI spend 的财务口径、团队归因、任务级 ROI、预算控制、异常告警。**

这更像“AI 时代的 SaaS FinOps”，而不是“帮你选哪个模型”。

**与他的 SaaS 背景的契合点**

契合：

- SaaS 创始人通常熟悉 billing、usage-based pricing、团队预算、权限、报表。
- 可以把已有 SaaS 财务/运营经验迁移到 AI 成本治理。

需要新能力：

- 接入 OpenAI / Anthropic / DeepSeek / Cursor / Claude Code 等不同 usage 数据。
- 把 token usage 映射到业务任务，而不是只做 API 账单展示。

**立即可做的小动作**

1. 访谈 3 类人：CTO、财务负责人、AI-heavy 产品负责人。重点问：  
   “你们现在怎么知道某个 AI 功能是否值得继续烧钱？”
2. 做一个只支持 2 个入口的 MVP：  
   OpenAI API + Claude Code 使用追踪，按团队/项目/任务聚合成本，并给出异常告警。

## 3. **Agent-ready 知识与技能包：把团队流程变成可执行资产**

**数据支撑**

- [screencap] PH：`Turn your team's real workflows into AI training data`，把真实工作流转成训练/执行数据。
- [greplica] PH：`Self updating wiki for coding agents`，代码库知识自动维护给 Agent 用。
- [k-skill] GitHub：韩国本地服务 Agent skill pack，798 forks。
- [reverse-skill] GitHub：逆向/渗透测试 Agent skill router pack，1819 forks。
- [simpleenglish-skill] HN：ASD-STE100 技术英语 Agent skill，119 评论。

**为什么这是机会**

本周很明显的信号：大家不只是在等更强模型，而是在给 Agent 喂“可执行上下文”。

缝隙在于：

- 企业内部 SOP、例外规则、客户语气、产品知识都散落在 Slack、Notion、CRM、工单里。
- 直接 RAG 不够，因为 Agent 需要的不只是“知道”，而是“按步骤做”。
- 通用 Agent 不懂行业本地规则；垂直 skill pack 开始出现强需求。

机会不是做大而全知识库，而是做：  
**把一个团队的高频流程录制、结构化、版本化，并发布成 Agent 可调用的技能包。**

尤其适合从具体 SaaS 场景切：

- 客服升级流程。
- 销售线索清洗。
- 客户成功续约风险判断。
- 产品反馈归类。
- 内部运营 SOP 执行。

**与他的 SaaS 背景的契合点**

契合：

- SaaS 创始人理解客户工作流、权限、组织知识、onboarding。
- 可以从“帮客户把产品用好”延伸到“帮客户把流程变成 Agent skill”。

需要新能力：

- 工作流捕捉与结构化。
- Skill schema / tool calling 设计。
- 版本管理、测试集、回归验证。

**立即可做的小动作**

1. 找 2 个熟悉的 SaaS 客户，让他们录屏完成一个高频流程：如“处理退款申请”或“把销售线索同步到 CRM”。  
   目标不是训练模型，而是抽象成 Agent 可执行步骤。
2. 做一个“流程转 skill”的手工 concierge 原型：  
   输入录屏 + SOP 文档，输出可被 Claude/Cursor/内部 Agent 调用的 markdown skill + 测试用例。

## 反直觉的 1 个观察

最热的不是“Agent 多强”，而是“Agent 为什么还不能完全信”。

高评论信号集中在怀疑与约束：

- [ai-product-gap] `AI doesn't generate working products, that's still your job`，267 评论。
- [autonomous-business-fail] AI 自主经营失败，234 评论。
- [ai-reasoning-wrong-reasons] `Is AI reasoning right for the wrong reasons?`，230 评论。
- [ai-writing-refusal] 拒绝在写作中使用 AI，117 评论。

这说明买方心理已经从“炫技期”进入“责任期”。  
创业机会不在承诺 10x 自动化，而在提供**可验证、可审计、可接管的 2x 自动化**。
